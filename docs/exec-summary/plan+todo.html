The goal

Build the prototype from the spec: a web app for one person that records income and spending in Thai baht.

It reads bank slips and receipts with Claude into a form you check before saving, lists records by month and shows pie charts by category.

A password protects it so it can go online later. Target build time: 2-3 hours.

Risks and how they are handled

RiskImpactHandled bySource
Claude misreads a Thai slip (amount, Buddhist-era year, income or expense).HighYou always check before saving; a warning shows when it is unsure; the year conversion is tested; one real slip is tried early in step 4.tasks/plan.md > Risks and Mitigations
The database tool will not install on Windows with this version of Node.MedUse a long-term-support version of Node and check it in step 1, before building on it.tasks/plan.md > Risks and Mitigations
The login check runs in a place where the usual signing tool is not available.MedUse the web's built-in signing tool, which works in both places.tasks/plan.md > Risks and Mitigations
Reading a slip takes longer than 15 seconds or fails.MedShrink the photo first, stop waiting after 30 seconds and fall back to an empty form.tasks/plan.md > Risks and Mitigations
The build runs over the 2-3 hour budget.MedKeep polish small. If late, cut in this order: the low-confidence warning, then editing (deleting stays), then the end-to-end test.tasks/plan.md > Risks and Mitigations
Secrets are uploaded to the public repository.HighThe ignore list is set up in step 1 before anything is saved to history, and files are checked before every upload.tasks/plan.md > Risks and Mitigations

Decisions already made

DecisionSource
One app holds both the screens and the behind-the-scenes parts; there is no separate server program.tasks/plan.md > Architecture Decisions
Records are kept in SQLite (a database stored in one file on your computer). No database server is needed.tasks/plan.md > Architecture Decisions
Money is kept as whole satang (baht times 100) so totals never drift from rounding.tasks/plan.md > Architecture Decisions
Reading a slip never saves anything. Only the form's Save button saves, so you always check first.tasks/plan.md > Architecture Decisions
One form is shared for typing by hand, checking a read slip and editing.tasks/plan.md > Architecture Decisions
Automatic checks use a pretend AI, so they never spend Claude credits.tasks/plan.md > Architecture Decisions
The password login is built last: it would slow down building and is low risk.tasks/plan.md > Architecture Decisions
Claude is asked to answer only with structured data; anything it cannot answer cleanly opens an empty form to fill in by hand.tasks/plan.md > Architecture Decisions

Working in parallel

At this size it is not worth splitting the work; one session builds the steps in order. Reading slips and the records list do not depend on each other and could run side by side if needed.
